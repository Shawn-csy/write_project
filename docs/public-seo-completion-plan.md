# Public SEO Completion Plan

Last updated: 2026-06-26

## Purpose

The public Next.js app already has route-level SEO metadata for the main public pages. This document defines the remaining work required before public SEO can be considered complete at the site level.

This is not a keyword-tuning checklist. The goal is a stable technical SEO contract:

- canonical public URLs are generated from one source of truth;
- crawlers can discover all intended public pages;
- non-indexable or retired surfaces are explicitly excluded;
- Open Graph, Twitter, and JSON-LD output are deterministic;
- SEO behavior is verified by tests and production checks.

## Current Assessment

### Already Strong

- `apps/public` owns the canonical public runtime.
- Public pages use Next.js App Router metadata:
  - `/`
  - `/read/[id]`
  - `/author/[id]`
  - `/org/[id]`
  - `/series/[name]`
  - `/tag/[name]`
  - static pages such as `/about`, `/help`, `/license`, `/privacy`, `/terms`
- `/read/[id]` has a dedicated SEO model in `apps/public/lib/readPageSeo.ts`.
- JSON-LD is emitted through `apps/public/lib/jsonLd.tsx`, avoiding ad hoc escaping.
- Read pages emit `CreativeWork` JSON-LD and `BreadcrumbList`.
- Entity and collection pages emit basic structured data.
- Public pages have canonical URLs and social metadata.
- Root layout has `metadataBase` pointing at the production domain fallback.

### Not Complete Yet

The public app has good page-level SEO, but site-level SEO still has structural gaps.

| Area | Current State | Risk |
|---|---|---|
| Default OG image | `DEFAULT_OG_IMAGE_PATH = "/og/homepage.png"` but the file is not present in `apps/public/public/og/` | Social preview image can 404 for pages without entity images |
| Sitemap ownership | `/sitemap.xml` is still generated by the backend and proxied through nginx | Public URL policy can drift from the canonical Next app |
| Sitemap author identity | Backend sitemap can fall back to owner IDs for `/author/{id}` | May submit non-canonical or 404 author URLs |
| Sitemap coverage | Series pages are now full public entity pages but are not currently included in the backend sitemap policy | Search discovery for series pages is weaker than the product surface |
| Robots ownership | `public/robots.txt` is still a root static file, not generated by `apps/public` | Robots policy can drift from Next-owned public routes |
| Static page metadata | Static pages define local `BASE_URL` constants instead of importing the shared SEO config | Small but real drift risk |
| Query URL policy | Homepage filters use query state; canonical policy exists for `/`, but crawl/noindex behavior is not locked by tests | Duplicate crawl paths can grow over time |
| SEO tests | Several pure SEO helpers have tests, but no route-wide contract covers sitemap, robots, OG fallback file existence, and representative page metadata together | Regression risk remains high |

## Non-Negotiable Principles

- Next.js public app owns public SEO contracts.
- Backend may provide data, but should not own public URL policy.
- Sitemap contains only canonical, intended-to-index URLs.
- Robots policy must not accidentally block Googlebot from public content.
- API and AI-agent policy must be explicit; generic SEO crawling and AI raw-content access are separate concerns.
- No route should rely on stale Vite behavior for SEO.
- Missing images, missing descriptions, and missing structured fields must have deterministic fallbacks.
- Tests must protect the contract, not implementation trivia.

## Target Architecture

```text
apps/public/lib/seo.ts
  BASE_URL
  site constants
  default images
  absolute URL helpers

apps/public/lib/publicSeoModel.ts
  canonical route builders
  sitemap URL model
  robots policy model
  indexability rules

apps/public/app/sitemap.ts
  Next MetadataRoute.Sitemap
  fetches public data through BFF/API boundary
  emits canonical public URLs only

apps/public/app/robots.ts
  Next MetadataRoute.Robots
  includes sitemap URL
  disallows workspace/admin/API surfaces

apps/public/app/**/page.tsx
  page-specific generateMetadata()
  page-specific JSON-LD using shared helpers

tests
  pure SEO model tests
  route contract tests
  sitemap/robots tests
```

## Canonical URL Policy

| Route | Indexing Policy | Sitemap Policy | Notes |
|---|---|---|---|
| `/` | index | include | Canonical discovery surface |
| `/read/[id]` | index | include all public scripts | Primary SEO target |
| `/author/[id]` | index | include only canonical Persona IDs with public scripts | Do not include owner fallback IDs |
| `/org/[id]` | index | include organizations with public scripts | Canonical org identity only |
| `/series/[name]` | index | include series with public scripts | Series page is now a real public entity page |
| `/tag/[name]` | indexable but lower priority | optional, default exclude unless product wants tag SEO | Thin aggregate; avoid sitemap bloat unless deliberate |
| `/about` | index | include | Product trust page |
| `/help` | index | include | Useful support page |
| `/license` | index | include | Useful licensing page |
| `/privacy` | index | include | Legal/trust page |
| `/terms` | index | include | Legal/trust page |
| `/gallery` | retired | exclude | Should remain absent from sitemap |
| `/dashboard`, `/studio`, `/edit`, `/settings`, `/admin` | noindex / disallow crawling | exclude | Workspace/editor surfaces |
| `/api/*` | generally disallow for generic crawlers | exclude | Public raw endpoints are AI-agent policy, not general SEO |

## Execution Plan

### Phase 1 — SEO Source Of Truth

Create a shared public SEO model owned by `apps/public`.

Proposed file:

```text
apps/public/lib/publicSeoModel.ts
```

Responsibilities:

- canonical URL builders:
  - `homeUrl()`
  - `readUrl(scriptId)`
  - `authorUrl(personaId)`
  - `orgUrl(orgId)`
  - `seriesUrl(seriesName)`
  - `tagUrl(tagName)`
  - static page URL helpers
- indexability decisions:
  - `isSitemapEligibleRoute(route)`
  - `shouldIncludeTagPageInSitemap()`
- URL encoding rules:
  - encode dynamic segment values exactly once
  - never mix encoded and decoded names in canonical URL builders

Acceptance criteria:

- Existing metadata code can import canonical builders instead of hand-building strings.
- Tests cover UTF-8 series/tag names and IDs with special characters.
- `/gallery` is explicitly excluded.

### Phase 2 — Default OG Image Contract

Add the real fallback image at:

```text
apps/public/public/og/homepage.png
```

Requirements:

- 1200×630 or compatible social preview ratio.
- Publicly served at `/og/homepage.png`.
- No auth, no redirect loop, no missing asset.
- Matches current public visual identity.

Tests:

- Static file existence test.
- `DEFAULT_OG_IMAGE_URL` resolves to an absolute URL.
- `pickPreviewImage(null)` returns the default URL.

Acceptance criteria:

- Pages without entity images never emit a missing `og:image`.

### Phase 3 — Next-Owned Sitemap

Implement:

```text
apps/public/app/sitemap.ts
```

The sitemap should fetch the minimum data needed to generate URLs:

- public scripts;
- canonical personas for public scripts;
- organizations for public scripts;
- series names from public scripts;
- static public pages.

Do not include:

- private scripts;
- owner fallback author pages;
- retired `/gallery`;
- workspace/editor/admin pages;
- generic filtered homepage query URLs.

Series inclusion rule:

- Include `/series/[name]` when at least one public script belongs to the series.

Tag inclusion rule:

- Default: exclude from sitemap unless a future product decision makes tag pages SEO targets.
- If included later, only include tags above a minimum content threshold.

Acceptance criteria:

- `/sitemap.xml` is generated by Next.
- nginx no longer proxies `/sitemap.xml` to backend.
- Sitemap has representative unit/integration tests.
- Sitemap includes at least one `/read/`, one `/author/` when persona exists, one `/org/` when org exists, and one `/series/` when series exists in fixture data.

### Phase 4 — Next-Owned Robots

Implement:

```text
apps/public/app/robots.ts
```

Policy:

- allow canonical public pages;
- disallow workspace/editor/admin pages;
- disallow generic `/api/` crawling for standard crawlers;
- include the sitemap URL;
- keep AI-agent policy explicit and separate from Googlebot.

Important distinction:

- `Googlebot` is for Search indexing.
- `Google-Extended` is not Google Search indexing. It controls Google AI product use. Do not use `Google-Extended` rules as a substitute for Googlebot validation.

Acceptance criteria:

- `/robots.txt` comes from Next or is otherwise explicitly routed to the canonical public policy.
- `Sitemap: https://open-scripts.shawnup.com/sitemap.xml` is present.
- `Googlebot` can crawl `/`, `/read/`, `/author/`, `/org/`, `/series/`.
- workspace routes remain disallowed.

### Phase 5 — Metadata Consolidation

Remove duplicated route-local SEO constants.

Targets:

- static pages currently defining local `BASE_URL`;
- dynamic pages hand-building canonical URLs;
- repeated site names and title suffixes.

Desired state:

- all routes import `BASE_URL`, `SITE_NAME`, `TITLE_SUFFIX`, and URL helpers from shared public SEO modules;
- static pages use shared metadata helpers where useful;
- no route declares its own production base URL string.

Acceptance criteria:

- `rg "const BASE_URL = process.env.NEXT_PUBLIC_BASE_URL" apps/public/app` returns no route-local copies.
- Static page metadata remains unchanged in rendered output.

### Phase 6 — Structured Data Consistency

Keep existing page-level JSON-LD, but make route policies explicit.

Required route models:

| Route | JSON-LD |
|---|---|
| `/` | `WebSite` with `SearchAction` |
| `/read/[id]` | `CreativeWork` + `BreadcrumbList` |
| `/author/[id]` | `Person` |
| `/org/[id]` | `Organization` |
| `/series/[name]` | `CreativeWorkSeries` |
| `/tag/[name]` | `CollectionPage` |
| static pages | optional `WebPage` if needed later |

Future improvement:

- add `BreadcrumbList` to author/org/series/tag pages if browser UX also exposes that hierarchy.

Acceptance criteria:

- JSON-LD output goes through `JsonLdScript`.
- No page writes raw `JSON.stringify(...).replace(...)` inline.
- Structured data tests assert important fields, not full incidental object snapshots.

### Phase 7 — Query URL And Duplicate Content Policy

Homepage filters use URL state. These query URLs are useful for sharing, but not all should be treated as canonical SEO pages.

Policy:

- `/` remains the canonical homepage.
- Query URLs should canonicalize to `/`.
- Sitemap must not include filtered query URLs.
- Do not add `noindex` to every query URL unless Search Console shows duplicate-indexing problems; canonical is the first line of defense.

Acceptance criteria:

- Homepage metadata canonical remains `${BASE_URL}/` regardless of query.
- Tests cover representative query URLs if route-level testing is added.

### Phase 8 — SEO Contract Tests

Add tests that protect the actual contract.

Recommended tests:

- `publicSeoModel.test.ts`
  - canonical URL builders;
  - encoded dynamic route values;
  - sitemap eligibility;
  - retired route exclusion.
- `sitemap.test.ts`
  - static pages included;
  - public scripts included;
  - private scripts excluded;
  - owner fallback author URLs excluded;
  - series URLs included;
  - tag URLs excluded by default.
- `robots.test.ts`
  - sitemap URL present;
  - public routes allowed;
  - workspace/admin/API routes disallowed.
- `ogImage.test.ts`
  - fallback asset exists;
  - fallback URL is absolute.

Acceptance criteria:

- Failing tests clearly indicate policy drift.
- Tests do not require live production network access.

### Phase 9 — Production Verification

After deploy, verify with production URLs.

Manual checks:

```bash
curl -I https://open-scripts.shawnup.com/og/homepage.png
curl -s https://open-scripts.shawnup.com/robots.txt
curl -s https://open-scripts.shawnup.com/sitemap.xml | head
curl -L -s https://open-scripts.shawnup.com/read/{known-id} | rg 'canonical|application/ld\\+json|og:image'
```

Search Console:

- submit or refresh sitemap;
- inspect:
  - homepage;
  - one read page;
  - one author page;
  - one org page;
  - one series page;
- confirm pages are crawlable and indexable.

Rich Results / structured data:

- validate representative read page JSON-LD;
- validate author/org/series pages for parse errors even when they do not qualify for rich results.

Acceptance criteria:

- Search Console does not report sitemap parse errors.
- No missing fallback OG image.
- No submitted 404 author URLs.
- Canonical selected by Google matches submitted canonical URL for representative pages.

## Implementation Order

Recommended order:

1. Phase 2 — add default OG image asset.
2. Phase 1 — create shared SEO model and URL builders.
3. Phase 3 — move sitemap to Next.
4. Phase 4 — move robots to Next.
5. Phase 5 — consolidate route metadata constants.
6. Phase 8 — add contract tests.
7. Phase 6 and 7 — structured data/query policy refinements.
8. Phase 9 — production verification.

Reasoning:

- The missing OG image is an immediate public-facing defect.
- URL builders should exist before sitemap/robots migrate.
- Sitemap/robots are the core site-level SEO contract.
- Tests should lock behavior before later refinements.

## Definition Of Done

- [x] `/og/homepage.png` exists and is served successfully.
- [x] `apps/public/app/sitemap.ts` owns sitemap generation.
- [x] `apps/public/app/robots.ts` owns robots policy.
- [x] nginx no longer proxies sitemap to backend.
- [x] Sitemap excludes owner fallback author URLs.
- [x] Sitemap includes canonical series pages.
- [x] Sitemap excludes retired `/gallery`.
- [x] Static pages use shared SEO constants/helpers.
- [ ] JSON-LD is emitted only through `JsonLdScript`. (Phase 6 — pending audit)
- [ ] Query URLs canonicalize to the base public route. (Phase 7 — pending audit)
- [x] SEO contract tests cover sitemap, robots, OG fallback, and representative metadata.
- [ ] Production Search Console validation is recorded after deploy. (Phase 9 — post-deploy)
