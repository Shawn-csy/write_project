# 工作室 UI／UX 重整：問題盤點與修改策略

日期：2026-10-29  
狀態：第一批可用性修正已部署 Dev；整體流程重整進行中。  
適用環境：`dev` 分支、`studio-dev-open-scripts.shawnup.com`。

## 1. 目標與範圍

讓使用者能快速找到正在寫的作品、直接編輯，並在同一個作品脈絡內完成公開資料、Demo 與發布操作。以工作流程、資訊架構和手機操作為優先，再統一視覺規則。

使用者已要求開始執行，並要求保留至少 20% 使用額度。以下目標與提案以階段紀錄區分已完成與尚待實作。修改與部署限 Dev；正式站、正式資料庫與正式部署流程均不在本計畫執行範圍。

## 3. 產品與資訊架構

### 3.1 主要導覽提案

| 入口 | 責任 |
|---|---|
| 作品 | 近期編輯、文件／資料夾、草稿、公開作品、外部作品；可依來源與狀態篩選 |
| 系列 | 系列基本資料、作品歸屬、章節排序與公開預覽 |
| 公開身份 | 台本師／聲演身份、筆名、簡介、社群、頭像、橫幅與組織關係 |
| 媒體庫 | 圖片管理與選用；入口實作前先盤點現有權限與功能 |
| 設定 | 帳號與偏好；具體項目先盤點現有設定 |

公開站保留清楚的外連入口。組織與廣告申請安排在相關管理區域，避免干擾寫作與發布主流程。實作前先確認既有入口與權限能完整映射。

### 3.2 文件與作品的關係

- 私人文件、大綱與資料夾保留獨立用途，不將每份文件自動當成待發布作品。
- 使用者選擇「準備發布」後，才開始顯示發布必填檢查。
- 作品清單可呈現站內與外部作品，保留來源標示與來源篩選；不將外部網址轉存為可編輯的站內正文。
- 先以導覽與資料投影整合入口，保留既有 script／external script ID 與 API 契約，避免為了畫面立即合併資料表。

### 3.3 單一作品操作脈絡

```text
作品列表
  ├─ 編輯正文（站內文件，直接進編輯模式）
  └─ 作品管理
       ├─ 內容：站內內容入口／外部來源連結
       ├─ 公開資料：名稱、摘要、身份、標籤、系列、封面、授權與分級
       ├─ Demo：演出連結與聲演資料
       └─ 預覽與發布：缺項確認、公開結果、取消公開
```

列表保留搜尋、排序、來源、狀態與原捲動位置。從編輯器或作品管理返回時，不重新丟失列表上下文。

## 4. 狀態與操作契約

| 使用者看到的狀態 | 定義 | 主要動作 |
|---|---|---|
| 草稿 | 尚未公開，沒有主動進入發布流程 | 繼續編輯 |
| 準備發布 | 使用者已選擇準備發布，仍可能缺少必要資料 | 完成發布資料 |
| 已公開 | 後端確認可在公開站存取 | 管理作品／查看公開頁 |

「可公開」是就緒程度，不與公開狀態混為一組互斥狀態。缺封面等建議項目與真正阻擋發布的必填項目分開顯示；私人草稿不因缺發布欄位出現警告。

準備發布是否需要持久化狀態，須先盤點現有資料模型。若需要 migration，另列欄位、預設值、回填與回復方式，不在視覺調整中隱含新增。

- 「儲存」清楚說明對公開頁的影響。先確認現行公開作品更新是否立即生效；若立即生效，按鈕應使用「儲存並更新公開頁」等明確文字。
- 「發布」只在必要資料符合規則時可執行；失敗保留輸入並顯示可處理原因。
- 不顯示尚未具備資料版本機制的「未發布修改」或「發布新版本」承諾。
- 刪除、取消公開、刪除身份放在次要／危險操作區；確認訊息列出對象與影響。是否可還原依現有 API 能力如實呈現。
- 導覽、切換作品、切換身份時處理未儲存變更；不因重整布局遺失輸入。

## 5. 表單與版面策略

### 5.1 發布與外部作品

發布表單統一為「基本資料／分類與展示／授權與發布」等清楚區段，Demo 與活動資料依情境提供入口。原有欄位先逐項對照，確保重排後資料仍可讀寫。

只有一套區段導覽；檢查清單只摘要真正缺少的必填項目，點擊後展開並定位欄位。一般編輯不自動啟動遮住內容的教學。

外部連結沿用「貼上連結 → 讀取 → 補資料 → 預覽 → 發布」流程。讀取失敗仍可手動補齊，重新讀取不得無提示覆寫使用者已編輯的欄位。

保留既有規則：公開站投稿須審核；工作室以自己的合法作者身份發布外部作品可直接發布。身份選擇、編輯權與刪除權由後端驗證。

### 5.2 身份與角色

身份可同時具有台本師與聲演角色。角色與一般興趣標籤分開理解，聲演資格保留自填身份或公開演出紀錄的既有規則。編輯身份後，其作品與演出關聯不可遺失。

單一身份以簡潔選擇器或直接編輯呈現；多身份時提供搜尋／切換。頭像和橫幅以預覽、選圖、裁切為主要操作，網址欄位放在補充入口。

### 5.3 共用視覺規則

- 一個頁面主標題、一個主要操作、一列列表工具；減少卡片包卡片。
- 間距採 4／8／12／16／24／32px 尺度。列表內距以 12–16px，區段間距以 24px 為基準。
- 後台正文與表單採清楚的無襯線字體；等寬字體限程式碼、識別碼等必要資料。
- 使用現有語意色 token 統一淺色／深色模式。文字對比至少符合 WCAG AA：一般文字 4.5:1，大字 3:1。
- 警告色保留給需要注意或阻擋的事件；選取、焦點、停用具有可辨識的不同樣式。
- 統一「發布／身份／台本師」用詞；一般介面不混用 PUBLIC、PRIVATE、Loading 等未翻譯文字。

### 5.4 RWD

桌面、平板、手機依任務重排。手機使用單欄與整頁垂直捲動，主要按鈕不可被裁切，避免表單內再嵌套固定高度捲軸。

手機列表顯示名稱、狀態、日期與主要動作；封面縮成輔助縮圖。搜尋獨立一列，排序與篩選使用完整可辨識控制項。次要操作移入具文字的選單。

系列與身份管理使用「列表 → 編輯 → 返回列表」，返回保留位置。手機頂部顯示目前頁面名稱；新增等重要圖示具清楚文字或可見替代入口。觸控目標以至少 44 × 44px 為基準。

## 8. 驗收與 Dev 發布策略

### 操作驗收

- [ ] 從工作室找到近期作品並直接進入編輯，無須先經過檢視模式。
- [ ] 私人大綱／空白文件可保存，不要求填發布資料。
- [ ] 計數與列表使用一致範圍；分頁載入不改變總量的意義。
- [ ] 必填缺項與可公開判斷一致，錯誤可直接定位並修正。
- [ ] 已公開作品儲存後的公開效果與按鈕文字一致。
- [ ] 外部作品可讀取、手填、預覽、發布、維護與依權限刪除；站外原始作品不受本站刪除影響。
- [ ] 台本師兼聲演的身份維護後，兩類公開資訊與關聯完整保留。
- [ ] 系列編輯、排序、返回與未儲存變更處理正常。
- [ ] 空資料、載入、請求失敗、無權限等狀態有清楚回饋。

### 裝置與視覺驗收

- [ ] 360／390／768／1280px 檢查主要流程，無頁面水平溢出與操作裁切。
- [ ] 手機軟鍵盤開啟後仍能看到輸入與儲存操作。
- [ ] 深色／淺色、鍵盤焦點、表單標籤與錯誤訊息均可辨識。
- [ ] 使用真正內容、長標題、多標籤、無封面、單一／多身份驗證布局。
- [ ] 保存桌面與手機畫面作為階段驗收證據，不能只以建置成功代替 UI 驗收。

### 工程與部署

依實際變更執行型別檢查、相關狀態與路由測試、Dev Studio 建置及必要流程驗證。狀態與權限變更須有對應驗證，不以純樣式測試替代。

Dev Studio 使用 `npm run build:dev-studio` 與獨立 Dev Compose 服務；操作以現有部署文件為準。每次發布記錄 commit／差異範圍與 Dev 建置來源；必要時可回復上一份 Dev bundle。資料 migration 若有新增，另行制定回復策略。

舊的 `/dashboard`、`/studio?tab=...`、`/community` 與作品連結須提供相容映射，避免書籤與站內跳轉失效。正式環境發布另行處理，不因 Dev 驗收通過自動發布正式站。
